# Contributing to Adventure-Game

First of all, thank you for considering contributing to **Adventure-Game**! 🎉

Whether you're fixing a bug, improving the code, adding new gameplay features, or enhancing the documentation, your contributions are greatly appreciated.

## Before You Start

Before making major changes, please open an Issue to discuss your idea. This helps avoid duplicated work and ensures the proposed changes fit the project's direction.

## How to Contribute

### 1. Fork the Repository

Click the **Fork** button on GitHub and clone your fork:

```bash
git clone https://github.com/YOUR_USERNAME/Adventure-Game.git
cd Adventure-Game
```

### 2. Create a Branch

Use a descriptive branch name:

```bash
git checkout -b feature/inventory-improvements
```

Examples:

- `feature/new-enemy`
- `feature/save-system`
- `bugfix/combat-crash`
- `docs/readme-update`

### 3. Make Your Changes

Please keep your changes focused on a single feature or fix.

When possible:

- Write clean, readable C++ code.
- Follow the existing project structure.
- Keep functions small and easy to understand.
- Avoid unnecessary code duplication.

### 4. Test Your Changes

Before submitting a Pull Request:

- Make sure the project compiles successfully.
- Verify that existing functionality still works.
- Test any new features you add.

### 5. Commit Your Changes

Use clear commit messages.

Examples:

```
Add inventory sorting
Fix combat damage calculation
Improve player class documentation
Refactor character generation
```

### 6. Push Your Branch

```bash
git push origin feature/inventory-improvements
```

### 7. Open a Pull Request

Include:

- A clear description of what changed.
- Why the change was made.
- Screenshots (if applicable).
- Reference any related Issues.

## Coding Guidelines

### C++

- Use meaningful variable and function names.
- Prefer `const` whenever possible.
- Keep formatting consistent.
- Remove unused code before submitting.
- Comment complex logic when necessary.

### Project Structure

When adding new features:

- Keep related files together.
- Reuse existing classes when appropriate.
- Avoid creating large monolithic functions.

## Types of Contributions

Contributions of all sizes are welcome, including:

- 🐛 Bug fixes
- ✨ New gameplay features
- ⚔️ Combat improvements
- 🎒 Inventory enhancements
- 👤 Character generation improvements
- 🌍 World expansion
- 📖 Documentation updates
- 🧹 Code refactoring
- ⚡ Performance improvements

## Reporting Bugs

When creating a bug report, please include:

- Operating system
- Compiler and version
- Steps to reproduce
- Expected behavior
- Actual behavior
- Error messages (if any)

## Feature Requests

Feature requests are welcome.

Please explain:

- What problem you're trying to solve.
- Your proposed solution.
- Any alternatives you've considered.

## Pull Request Checklist

Before submitting, please confirm:

- [ ] The project builds successfully.
- [ ] I tested my changes.
- [ ] My code follows the project's style.
- [ ] I updated documentation if needed.
- [ ] My Pull Request focuses on a single feature or fix.

## Code of Conduct

Please be respectful and constructive.

We aim to maintain a welcoming environment for everyone regardless of experience level.

## Questions?

If you're unsure where to start, feel free to open an Issue and ask. New contributors are always welcome!

Happy coding! 🎮
